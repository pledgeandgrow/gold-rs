# Component Trait System Design

> Goal 11 — Define `Component` as a trait with clear lifecycle. Support both function components (ergonomic) and trait components (flexible).

---

## Design Goals

- **Familiar** — Function components feel like React (but without hook rules)
- **Flexible** — Trait components for complex stateful logic
- **Zero-cost** — Function components compile to trait impls with no runtime overhead
- **Lifecycle-aware** — Clear `create`, `render`, `update`, `destroy` phases
- **Props-typed** — Compile-time prop validation via derive macro

---

## Two Component Styles

### 1. Function Components (ergonomic, default)

```rust
use rye::prelude::*;

#[derive(Props)]
struct CounterProps {
    initial: i32,
    #[prop(optional)]
    step: i32,
}

#[component]
fn Counter(props: CounterProps) {
    let count = use_signal(|| props.initial);
    let step = props.step.unwrap_or(1);

    div {
        h1 { "Count: " {count} }
        button { onclick: count += step, "+" }
        button { onclick: count -= step, "-" }
    }
}
```

**What `#[component]` generates:**
```rust
// Auto-generated by the macro
impl Component for Counter {
    type Props = CounterProps;

    fn create(props: Self::Props) -> Self {
        Self { props, count: Signal::new(props.initial) }
    }

    fn render(&self) -> Element {
        // The function body, wrapped in template!
        template! {
            div {
                h1 { "Count: " {self.count} }
                button { onclick: move |_| *self.count += self.step, "+" }
                button { onclick: move |_| *self.count -= self.step, "-" }
            }
        }
    }
}
```

### 2. Trait Components (flexible, advanced)

```rust
use rye::prelude::*;

#[derive(Props)]
struct DataTableProps {
    rows: Vec<Row>,
    sortable: bool,
}

struct DataTable {
    props: DataTableProps,
    sort_key: Signal<Option<String>>,
    sort_dir: Signal<SortDir>,
}

impl Component for DataTable {
    type Props = DataTableProps;

    fn create(props: Self::Props) -> Self {
        Self {
            props,
            sort_key: Signal::new(None),
            sort_dir: Signal::new(SortDir::Asc),
        }
    }

    fn render(&self) -> Element {
        let sorted_rows = use_memo(move || {
            let key = self.sort_key();
            let dir = self.sort_dir();
            sort_rows(&self.props.rows, key, dir)
        });

        div {
            class: "data-table",
            For each(row in sorted_rows()) {
                tr {
                    key: row.id,
                    td { {row.name} }
                    td { {row.value} }
                }
            }
        }
    }

    fn destroy(&mut self) {
        // Cleanup: cancel pending fetches, release resources
        log::info!("DataTable destroyed");
    }
}
```

## Component Trait Definition

```rust
/// The core component trait.
///
/// Every UI component implements this trait.
/// Function components get an auto-generated impl via `#[component]`.
pub trait Component: 'static {
    /// The typed props for this component.
    type Props: ComponentProps;

    /// Called once when the component is first mounted.
    /// Initialize state, signals, and resources here.
    fn create(props: Self::Props) -> Self;

    /// Called whenever the component needs to render.
    /// Read signals here — their dependencies are tracked automatically.
    fn render(&self) -> Element;

    /// Called when any prop changes (for prop-driven updates).
    /// Return `true` if the component should re-render, `false` to skip.
    /// Default: always re-render on prop change.
    fn should_update(&self, _old: &Self::Props, _new: &Self::Props) -> bool {
        true
    }

    /// Called once when the component is unmounted/destroyed.
    /// Clean up resources, cancel async operations, etc.
    /// Default: no-op.
    fn destroy(&mut self) {}
}

/// Marker trait for component props.
/// Auto-implemented by `#[derive(Props)]`.
pub trait ComponentProps: 'static {
    /// Create an empty/default version of the props (all optional fields default).
    fn empty() -> Self;
}
```

## Lifecycle Flow

```
Component Lifecycle:
┌─────────────────────────────────────────────┐
│  create(props)                              │
│  └─ Initialize state, signals, resources    │
│  └─ Run setup effects                       │
├─────────────────────────────────────────────┤
│  render()                                   │
│  └─ Read signals (auto-tracked)             │
│  └─ Return Element tree                     │
├─────────────────────────────────────────────┤
│  [Signal changes] → render() called again   │
│  └─ Only if signal was read in last render  │
├─────────────────────────────────────────────┤
│  [Props change] → should_update()           │
│  └─ If true → render()                      │
│  └─ If false → skip                         │
├─────────────────────────────────────────────┤
│  destroy()                                  │
│  └─ Cleanup effects run                     │
│  └─ Signals dropped                         │
│  └─ Resources cancelled                     │
└─────────────────────────────────────────────┘
```

## Props System

### `#[derive(Props)]` macro

```rust
#[derive(Props)]
struct ButtonProps {
    /// Required prop — must be provided.
    label: String,

    /// Optional prop — defaults to None.
    #[prop(optional)]
    disabled: bool,

    /// Optional with default value.
    #[prop(default = "primary")]
    variant: String,

    /// Spread remaining attributes onto the element.
    #[prop(extend)]
    extra_attrs: Vec<(String, String)>,

    /// Children — for wrapper components.
    #[prop(children)]
    children: Vec<Element>,
}
```

### Props comparison

Props are compared using `PartialEq` (auto-derived). If props haven't changed, `should_update` returns `false` and `render` is skipped. For complex props (Vec, HashMap), the developer can override `should_update` for fine-grained control.

### Children

```rust
#[derive(Props)]
struct CardProps {
    title: String,
    #[prop(children)]
    children: Vec<Element>,
}

#[component]
fn Card(props: CardProps) {
    div {
        class: "card",
        h2 { {props.title} }
        div { class: "card-body", {props.children} }
    }
}

// Usage:
Card {
    title: "My Card",
    p { "Content goes here" }
    p { "More content" }
}
```

## Component Context

Every component has an associated **context** — a scope that owns signals, effects, and resources. This context is automatically created by `create()` and destroyed by `destroy()`.

```rust
/// Internal — the component's execution context.
pub struct ComponentContext {
    /// Signals owned by this component.
    signals: Vec<SignalHandle>,
    /// Effects owned by this component.
    effects: Vec<EffectHandle>,
    /// Resources owned by this component.
    resources: Vec<ResourceHandle>,
    /// Cleanup functions registered via on_cleanup().
    cleanups: Vec<Box<dyn FnOnce()>>,
}

impl ComponentContext {
    /// Drop all owned resources — called on destroy().
    fn drop_all(&mut self) {
        for cleanup in self.cleanups.drain(..) {
            cleanup();
        }
        // Signals, effects, resources are dropped automatically
    }
}
```

## Comparison with Competitors

| Feature | React | Vue | Dioxus | rye |
|---|---|---|---|---|
| Component style | Function only | Function + Object | Function + Trait | Function + Trait |
| Lifecycle | Hooks (useEffect) | Options API hooks | `on_mounted`, etc. | `create`, `render`, `destroy` |
| Props typing | PropTypes (runtime) | TypeScript (erased) | Rust struct | Rust struct + derive |
| Prop defaults | defaultProps | `default:` | Manual | `#[prop(default)]` |
| Children | `props.children` | Slots | `props.children` | `#[prop(children)]` |
| Should update | Manual memo | Automatic | Automatic | Automatic + override |
| Hook rules | Yes (strict) | No | No | No (signals anywhere) |
